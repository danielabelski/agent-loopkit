# agent-loopkit v0.1.0 — initial public release

The first public release of `agent-loopkit`: a catalog of reusable playbooks for autonomous AI agent loops.

## What's in this release

- **Catalog scaffold**: README, RECIPE_TEMPLATE, CONTRIBUTING, SECURITY, CODE_OF_CONDUCT, CHANGELOG, LICENSE.
- **Validation tooling**: `scripts/validate_recipe.py` (12 required sections + secrets scan + table row minimums) and `scripts/validate_repo.py` (repo-level structure).
- **Test suite**: 32 pytest tests covering both recipes + the validators themselves.
- **CI workflow**: `.github/workflows/validate.yml` runs validators + pytest + a defense-in-depth secrets scan on every PR.
- **Recipe #1 — `tgo-full-funnel-autopilot`**: 3×/day local-business Facebook lead-funnel loop extracted from a production cron. Variables table (13 rows), failure modes (9 rows), verification checklist (11 items).
- **Recipe #2 — `etsy-logo-pack-pipeline`**: 3-stage script-only pipeline (generate → Etsy draft → Pinterest pin) extracted from 3 production crons. Variables table (19 rows), failure modes (9 rows), verification checklist (12 items).
- **Branding**: SVG banner + logo + icon (teal/cyan + amber kit accent).
- **Scaffold template**: `templates/scaffold/` for new recipes.

## Provenance

Both recipes were extracted from production cron flows running inside the maintainer's agent runtime. The recipe shape is generic; the specifics (business name, region, brand asset, contact CTA) are placeholders the operator must replace before deploying.

See [`references/about.md`](references/about.md) for the full provenance.

## Quickstart

```bash
git clone https://github.com/ooovenenoso/agent-loopkit
cd agent-loopkit
ls recipes/                              # browse the catalog
cp -r recipes/<recipe-slug> ~/my-loop    # pick a recipe
```

Then read the recipe's `RECIPE.md` (start with the "Variables you must change" table).
