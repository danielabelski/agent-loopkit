# Code of conduct

This repo follows a small set of community norms. They're short on purpose.

## Be useful

If you're contributing a recipe, PR, or issue, ask first: does this make the catalog better for someone other than me? A "yes" answer is the bar.

## Don't be clever

Recipes should be **boring on purpose**. They're meant to be copied, adapted, and shipped — not admired. Cleverness is a cost; clarity is a gift.

## Fix what you break

If a recipe you wrote breaks for someone else, you fix it. If you can't (e.g., you no longer use the platform), deprecate the recipe explicitly: add a `status: deprecated` header in `RECIPE.md`, link to the replacement if there is one, and keep the directory around for at least one release so people have time to migrate.

## Disagree in writing

If a reviewer's call seems wrong, push back in the PR thread with reasoning, not with "well actually". Closed PRs without explanation are fine — but only if you've made the case first.

## No harassment, no spam

Standard norms apply. No personal attacks, no advertising your own services in unrelated issues, no drive-by PRs that are just promotion.

## Enforcement

Violations can be reported privately to the maintainer (see GitHub profile). The maintainer will respond within one week. Repeated violations may result in a temporary or permanent ban from the repo.

## Scope

This applies to:

- GitHub issues, PRs, and discussions on this repo.
- Any communication channels the maintainer creates around the repo (none exist yet, but if/when they do, this CoC applies).

It does not apply to:

- Recipes' own customer interactions (those are between the recipe's operator and their customers).
- Third-party platforms mentioned in recipes (their own terms apply).
